# Pharmexia v2.0.1 analytical verification package

Contents
- `oncox.py`  v2.0.1 (v2.0.0 plus strand-aware matching; see `strand_aware_matching.patch`)
- `data/star_allele_rules.json`  rule file used for the verification (generated by `build_rules.py` from PharmCAT v3.4.0 phenotype tables). **Compare it with the rule file in your local project before publishing; if they differ, re-run everything with yours.**
- `benchmark.py`  scenarios A-D (157 scenarios) and allele-catalogue coverage (scenario B)
- `strand_test.py`  scenario E (forward-strand vs coding-strand input for TPMT and VKORC1)
- `make_tests.py`  writes the six synthetic VCF files and runs them end to end
- `test_files/`  S01-S06 VCF files and S02 CSV
- `results/`  per-scenario output

Reproduce
1. `git clone --depth 1 https://github.com/PharmGKB/PharmCAT` and set `PC` in `build_rules.py` and `benchmark.py` to its `src/main/resources/org/pharmgkb/pharmcat` folder.
2. `python build_rules.py` (writes `data/star_allele_rules.json`)
3. `python benchmark.py` then `PGX_MODULE=oncox python strand_test.py`

`stubs.py` replaces PySide6, FastAPI and uvicorn with mocks so the engine runs headless. To reproduce the v2.0.0 strand defect, run `strand_test.py` against the unpatched v2.0.0 `oncox.py` (28 of 30 combinations discordant).
Expected: 0 discordant in scenarios A, C, D and E; 96 of 96 undetectable alleles inconclusive.
